Creator Studio

One app for making and repairing custom items, armour, weapons, NPCs, bosses and animations for your server. It runs on its own, away from the game. Nothing in the game changes until you press Port to game.

Open it

  1. Open the Creator Studio folder.
  2. Double-click Start Creator Studio.cmd (on a Mac or Linux, run start-creator-studio.sh). A black window opens and stays open; that is the app running. It needs Node.js 18 or newer and nothing else.
  3. Your browser opens http://localhost:4777. If it does not, type that address in yourself.
  4. Close the black window when you are done. Your drafts are saved as you go.

The app only answers on this computer. It reads the game's files as often as it likes; it writes to them only during a port, a repair or an undo, and it copies the old files to the server's backups folder first every time.

Folders and caches

The app needs to know two things: where your game is, and where the RS3 cache you want to port from is. Both are buttons at the top right. A green dot means it is set; a yellow dot means it is not.

Game folder

  • Choose your game server folder, the one with data\definitions inside. Port to game then writes into it.
  • The window lists what your server can load: custom items, custom NPCs, custom animations, cape particles. Anything marked red is still written, but will not show in game until the server can load it.
  • No server? Choose an OSRS cache instead (a folder with main_file_cache.dat2). Everything works, and the button reads Export files: your work is written to the app's own export folder to pass on.

RS3 cache

  • Search this computer looks in Downloads, Desktop, Documents and the app's own folders, and lists every cache it finds.
  • Or click through the folders yourself, or paste a path and press Enter. When you reach a cache, Use this folder appears.
  • A cache put in the app's rs3-cache folder is found by itself. The note inside that folder says what a cache looks like and where people get one.
  • The app tests the cache as it loads it and tells you if any part cannot be read. It was built on build 950.

Caches are not part of the app. RuneScape's game data belongs to Jagex; the app only reads the copy you point it at. Your choices are saved in config.json.

The screen

Left: what to open

  • Game items and Game NPCs: everything in the game, including your custom items and the bosses. Search by name or id.
  • RS3 items: every item in your RS3 cache, ready to port.
  • Animations: the custom animations in the game, and New animation.
  • My drafts: things you are working on. A draft is not in the game until you port it.
  • Ported: everything the app has put in the game, each with Undo this port.

Middle: the model

  • Drag to rotate. Right-drag or Shift-drag to move. Scroll to zoom. Double-click or Reset view to put the camera back.
  • Item model shows it as it lies on the ground. Worn, male and Worn, female put it on a player.
  • Animation plays any of 24 player animations on the worn view. Stretch colours paints faces red where they stretch.
  • Hover a face to read its number, colour and bone label under the picture.

The two bars at the top show how full the item and NPC packets are. The game sends all custom items to each player in one packet with a fixed size, so the app checks the size before every port and refuses one that would not fit.

Step-by-step tutorials

Pick a job. Button names are written exactly as they appear in the app. Under each one is what Claude types to do the same job without the app.

How models move, and the two ways they break

Every point of a model belongs to one bone. An animation turns each bone around a pivot. The game works the pivot out for itself: it is the middle of the points that carry the pivot's bone number. Move the sliders and switch the fault on to see what you saw in game.

A joint with no pivot

This was the Elite tectonic top. The robe hides the player's arms, and the arms were the only thing marking the shoulder. With nothing left to mark it, the game turned the sleeve around the floor.

Two parts that touch at one point

This was the Angel of Death's greaves, and Vorago 644 times over. The game joins any two points that sit on exactly the same spot. One plate then has a corner that follows the other leg.

That second fault is why earlier checks kept passing: they tested the model file. The app tests the model as the game builds it. In the app that is Check it as the game builds it on any NPC, and Check for stretching on any worn item.

Some stretch is normal. Cloth in the real game stretches on purpose: a real Virtus robe bottom reaches 7.6 times. So the app measures your item next to the real item it plays as, and only cuts faces that stretch further than that.

Colours

The game has no free colour picker. Every face has one of 65,536 colours made of three numbers. The app converts for you; this does the same sum.

Two ways to change colour in a draft. Swap replaces one colour everywhere and costs nothing: the game does the swap itself, so no new model file is made. Paint changes single faces with Brush (one face), Fill (touching, same colour) or Whole body part. Paint last: if you change the model's shape afterwards, the paint no longer lines up and the app drops it with a warning.

  • Before writing, the app shows exactly what will happen. Nothing is written until you press the orange button in that box.
  • The old files are copied to the server's backups\creator-studio-... folder first.
  • A server that runs under nodemon restarts once by itself, so players are logged out for a moment. It usually takes about 20 seconds, sometimes a minute and a half. The app waits and tells you whether it came back clean.
  • Ported tab, Undo this port puts everything back. Files a port created are moved to a _to_delete folder next to the server; the app never deletes anything of yours.
  • With no game server, the same files go to the app's export folder and nothing is installed anywhere.

What went wrong before, and why

Three real faults from the server this app was built on. All three were ported by asking an AI to do it by script. Each script tested its own output file and passed. Each was wrong in the game for a reason the file could not show.

Elite tectonic robe top

Seen in game: the arm stretching, and a fix that made it worse.

Cause: RS3 marks each joint with tiny hidden triangles. The port threw them away. The top also hides the player's own arms, which were the only other thing marking the shoulders. So the sleeves turned around the floor.

Fix: rebuilt from the RS3 model with the hidden markers kept. Worst stretch 92.9 times down to 4.9, next to 4.6 for real Virtus.

Angel of Death armour

Seen in game: a grey part stretching from leg to leg.

Cause: the left and right greaves each had a corner on the same point between her shins. The game joined them. Five silver triangles of the left greave then followed the right leg, by up to 190 units.

Fix: one point moved by 1 unit. She now measures the same as plain Nex. The pet uses the same model, so it is fixed too.

Vorago

Seen in game: a pale, spiky shape with big dark sheets across the chest when he attacks.

Cause: four things. 21 joints had no pivot. The port cut him into rigid plates that shared corners, and the game welded 644 of them back together. The colours used the texture alone, which lost the brown paint on the rocks and the cyan lines. And 1,176 faces of glow, dust and aura were baked into solid shards.

Not fixed yet. A rebuild from the RS3 model brought the measured stretch from 111 times down to 1.2, and was put in the game on that number. In game his face was gone and the movement still looked wrong. A rule meant to drop see-through glow layers had dropped the face too, and nobody had compared a picture with the real creature first.

The rules that came out of it: test what the game builds, never only the file. Keep RS3's hidden marker triangles; they are the joints. And look at a picture next to the real thing before porting, because a good number is not the same as a good model.

Asking an AI helper

Claude, or any other coding assistant, uses the same engine through a command line, so anything in the app can be asked for in a sentence. Open it in the Creator Studio folder: CLAUDE.md and AGENTS.md there are its rules, and docs\AGENT-GUIDE.md explains every command, how to check and load a cache, how each fault is found and fixed, and the safety rules.

Asks that work well

  • "Port the RS3 Zaros godsword as a new weapon that plays as the Armadyl godsword. Show me a render before you port it."
  • "The shoulders on item 50334 look wrong when I cast. Check it and tell me what you find."
  • "Make an animation for players: both arms up, then a bow. About two seconds."
  • "Check Vorago as the game builds him and repair anything it finds."
  • "Make a blue copy of the abyssal whip called Frost whip."

What it should do every time

  • Run a dry run first and read the problems and warnings.
  • Make a picture and look at it, because it cannot see your game.
  • Write once, so the server restarts once.
  • Check the server came back clean, and undo if it did not.
  • Tell you what it measured and what still needs your eyes in game.
cd "<the Creator Studio folder>"
node cli.js help                              # every command
node cli.js status                            # folders in use, what the server can load, free ids
node cli.js setup                             # choose folders; lists every server and cache it can see
node cli.js rs3check                          # can this RS3 cache be read?
node cli.js search rs3 zaros godsword         # find things
node cli.js diagnose item 50334               # worn item: stretch and pivots
node cli.js gamecheck npc 17015               # NPC or boss as the game builds it
node cli.js anim joints player                # joints you can pose
node cli.js port <draft>                      # dry run
node cli.js port <draft> --write              # into the game
node cli.js ports                             # what was ported, with undo keys
node cli.js restart-status                    # did the server come back clean

Not built yet

These are not in the app yet.

  • Area porting from RS3. Not started in the app.
  • RS3 caches in other forms. Only the flat-file layout is read. A cache copied out of a game install (.jcache files) is not.
  • Object creator and placing objects on the map. Not started. In game, ::object still works by hand.
  • Flow editor for fire cape and infernal cape style moving textures. Not started. The app cannot put a texture on a face yet.
  • Porting a new RS3 boss's animations. The app rebuilds a boss against animations that are already converted. Converting new ones is still the old scripts.
  • Zuk's animations use a newer system the app lists but cannot play or edit.
  • Room for animations. The game sends all custom animations in one 64 KB packet. 47 KB is used. Lifting that limit needs a change to the game client.
  • Master cape emblems. Porting a new RS3 cape brings the cape and its particles, but not the skill emblem on the back.
